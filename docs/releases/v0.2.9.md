# Release v0.2.9

breaking: false

## Summary

Provenance detection hotfix for derived repositories affected by immutable historical release tags.

## Fixed

- Prefer a valid recorded `template_commit` that can be resolved in the source repository.
- Fall back to the version tag only when the recorded source commit cannot be resolved.
- Prevent the updater from replaying changes from a stale immutable tag after a derived repository already contains the lifecycle fix.
- Document the one-time bootstrap for repositories that still run the previous workflow detector.

## Incompatible changes

None.

## Migration

The immutable `v0.2.6`, `v0.2.7`, and `v0.2.8` tags must not be moved or reused. A derived repository that already applied the lifecycle fix but still has the pre-`v0.2.9` workflow must first update `.github/workflows/template-update.yml` in a reviewed manual PR, preserving its `TEMPLATE_UPDATE_TOKEN` settings. After that PR is merged, rerun the template update workflow. Repositories based on older releases should follow the documented legacy bridge before updating to `v0.2.9`.
