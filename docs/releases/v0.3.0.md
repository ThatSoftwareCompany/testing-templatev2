# Release v0.3.0

breaking: true

Authentication and authorization are now part of the canonical Go API template. This release remains backend-only and does not modify the separate frontend template.

## Added

- Cookie-based administrator login, refresh, logout, CSRF, and current-user endpoints.
- Ed25519/EdDSA access JWTs with strict issuer, audience, key ID, subject, time, and algorithm validation.
- Opaque refresh tokens stored only as SHA-256 hashes, with rotation, family revocation, and reuse detection.
- Argon2id password hashing with 15–128-character password validation.
- PostgreSQL roles and permissions with deny-by-default authorization.
- Protected `GET /api/v1/internal/errors?endpoint=<path>` requiring `errors:read`.
- Interactive `go run ./cmd/auth -command create-admin` provisioning command.
- Development Ed25519 key generation script that writes only to ignored local storage.
- Authentication migrations for users, roles, permissions, refresh tokens, and login attempts.
- Unit, HTTP, and PostgreSQL integration coverage for the authentication security contract.

## Configuration changes

When `DATABASE_ENABLED=true`, the API now requires:

- `AUTH_PRIVATE_KEY_FILE`
- `AUTH_PUBLIC_KEY_FILE`
- `AUTH_KEY_ID`
- `AUTH_JWT_ISSUER`
- `AUTH_JWT_AUDIENCE`
- `AUTH_CSRF_SECRET` with at least 32 bytes

`AUTH_ACCESS_TOKEN_TTL` defaults to `15m`. `AUTH_REFRESH_TOKEN_TTL` defaults to `720h` and must remain between 7 and 30 days. When `DATABASE_ENABLED=false`, the process still starts and auth routes return `503 service_unavailable`.

## Migration instructions

1. Configure PostgreSQL and run `go run ./cmd/migrate -command up`.
2. Generate or mount the Ed25519 PEM files outside the repository.
3. Configure the JWT metadata and a secret CSRF value outside the repository.
4. Run `go run ./cmd/auth -command create-admin` to provision the first user.
5. Review the generated repository's update diff, especially managed workflows, cookies, CORS, and `internal/app/routes.go`, before merging.

All session cookies are HttpOnly, have no `Domain`, and use `Secure=false`/`SameSite=Lax` in development and test or `Secure=true`/`SameSite=Strict` in production. Tokens are never returned in JSON. There is no public registration, password recovery, Google OAuth, access-token denylist, or frontend change in this release.

## Compatibility

The minimum compatible Go version remains `1.26.0`; CI and Docker validate Go `1.26.7`. PostgreSQL compatibility remains `16+`. Because this release adds required auth configuration for database-backed startup and a new migration, it is a breaking template update and requires explicit review in derived repositories.
