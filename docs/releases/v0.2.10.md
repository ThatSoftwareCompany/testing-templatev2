# Release v0.2.10

breaking: false

## Summary

Updater hardening for generated repositories with custom module paths, pre-applied template files, and application-specific changes.

## Added

- Safe detection of template files that are already applied, including harmless YAML formatting differences.
- Import of source base blobs before three-way merge attempts.
- Explicit reporting for unresolved or unapplied template changes.
- Lifecycle coverage for clean-room repositories, generated README values, pre-applied files, legacy module paths, route preservation, and semantic conflicts.

## Fixed

- Normalize only the appropriate Go patch content when applying updates to repositories with custom module paths.
- Do not update template provenance after a partial or failed patch.

## Incompatible changes

None.

## Migration

Repositories with a clean working tree can update normally. Repositories with historical or manually customized template-managed files must review the reported paths, preserve intentional application changes, resolve conflicts manually, run the derived repository test suite, and then record the new template provenance before committing.
